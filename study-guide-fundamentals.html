PART 01 · CH 1

LLM 기반 의사결정 구조

1.1 – 1.4

1.1 – 1.3LLM은 에이전트의 "두뇌"다

에이전트는 결국 반복되는 질문 하나로 움직인다 — "지금 상태에서 다음에 뭘 해야 하지?" 이 질문에 답하는 판단 엔진이 LLM이다. 매 단계마다 지금까지의 대화·관찰 결과를 LLM에 입력하면, LLM은 다음 행동을 텍스트(또는 도구 호출)로 출력한다. 이 출력이 다시 다음 단계의 입력이 되면서 하나의 루프가 만들어진다.

1.4두 가지 설계 방식

이 루프를 실제로 짤 때는 크게 두 갈래로 나뉜다. 단계를 사람이 미리 정해두느냐, LLM이 매번 스스로 정하게 하느냐의 차이다.

PART 01 · CH 2

에이전트를 구성하는 3가지 핵심 부품

2.1 – 2.4

2.1.1추론 부품 ① — ReAct (생각 → 행동 → 관찰)

"생각하고, 행동하고, 관찰하고, 다시 생각한다"를 반복하는 구조. 매 반복에서 LLM은 먼저 상황을 짧게 추론(생각)한 뒤 행동을 고르고, 그 결과(관찰)를 다시 다음 생각의 재료로 삼는다.

2.1.2추론 부품 ② — Reflection (생성 → 비평 → 수정)

초안을 일단 만든 뒤, 스스로(또는 별도 평가 단계에서) 그 초안을 비평하고 수정 지시를 반영해 다시 쓰는 구조. 충분히 좋다고 판단될 때까지 이 루프를 반복한다.

2.2 – 2.3 추론만으로는 부족하다. LLM은 자기 안의 지식만으로 실시간 정보나 정확한 계산을 다룰 수 없고, 대화가 길어지면 앞의 맥락도 흐려진다. 이를 보완하는 두 부품이 도구 호출과 메모리다.

2.2 도구 호출

외부 지식 활용

LLM이 스스로 풀 수 없는 것 — 실시간 검색, 정확한 계산, DB 조회 — 을 함수(도구)로 위임하고, 그 결과를 다시 판단 재료로 받는다.

2.3 메모리

기억력

단기 메모리는 지금 대화의 맥락을, 장기 메모리는 세션을 넘어 유지되는 사용자 정보를 담당한다. 아래 비교 참고.

2.4 종합

ReAct 기반 LLM 에이전트

추론(ReAct) 루프 안에서 필요할 때마다 도구를 호출하고, 메모리로 맥락을 유지하는 형태로 세 부품이 하나의 에이전트에 결합된다.

단기 메모리

지금 이 세션의 대화 이력. 길어지면 트리밍하거나 요약해서 관리한다.

장기 메모리

세션이 끝나도 남는 사용자 프로필·이력. 다음에 만나도 맥락을 이어갈 수 있게 한다.

목적에 따른 아키텍처 설계 기준

3.1 – 3.3

3.1 – 3.2싱글 에이전트 vs 멀티 에이전트

싱글 에이전트는 하나의 LLM이 여러 도구를 갖고 스스로 판단해 처리하는 구조다(웹 검색, 코딩, RAG 에이전트가 대표적). 멀티 에이전트는 역할이 다른 여러 에이전트가 협업하는 구조로, 7장에서 다룬 네트워크·슈퍼바이저·계층형 패턴이 여기 해당한다.

3.3어떤 에이전트를 설계해야 할까

기준은 하나다 — 역할이 여러 개이고 서로 성격이 달라서 하나의 프롬프트에 다 담기 버거워지는 순간, 쪼갤 때가 된 것이다.

PART 02 · CH 5

랭그래프 기반 에이전트 설계

5.1 – 5.2

5.1왜 랭그래프인가

에이전트는 한 번 호출로 끝나지 않고 여러 단계를 거치며 상태를 유지한다. 랭그래프는 이 흐름을 그래프(상태·노드·엣지)로 표현해 로직을 명확하게 설계·시각화(랭그래프 스튜디오)할 수 있게 해준다.

5.2기본 개념 4가지 — State · Node · Edge · 조건부 엣지

Phase 0 체크리스트에서 "숙지"만 표시해뒀던 그 개념들이 여기서 나온다. State는 그래프 전체가 공유하는 데이터, Node는 상태를 받아 처리하는 실행 단위, Edge는 다음 노드로 가는 경로, 조건부 엣지는 상태값에 따라 경로를 갈라주는 분기다.
