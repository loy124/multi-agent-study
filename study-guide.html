멀티 에이전트 노선도

LangGraph 멀티 에이전트를 지하철 노선도로 바꿔보면 이해가 쉬워진다. 정거장은 에이전트, 선로는 핸드오프 경로, 환승역은 슈퍼바이저다. 결국 모든 패턴의 차이는 딱 하나 — 다음 정거장을 누가 정하는가.

환승 안내 — 용어 대응표

노선도 용어 ↔ LangGraph 용어

  • 정거장STATION = 에이전트(Agent) — 그래프의 노드 하나
  • 선로 / 노선RAIL / LINE = 핸드오프 경로 — 노드 사이의 엣지
  • 환승TRANSFER = Command로 다음 노드 + 상태 업데이트 지정
  • 환승역 / 허브HUB = 슈퍼바이저 — 하위 에이전트를 도구처럼 호출
  • 종착역TERMINUS = 최종 응답이 사용자에게 반환되는 지점

7.1.1 – 7.1.4 · Phase 1 상세 노선도

4개 노선 비교

N

네트워크선

NETWORK PATTERN

중앙 관제소 없이 정거장끼리 서로 직접 연결된 노선. 각 역이 스스로 "다음 역은 여기"라고 판단해 환승시킨다.

라우팅 결정자
각 에이전트 스스로. 처리 중 "이 다음은 저 역이 낫겠다" 싶으면 Command로 직접 넘긴다.
통신 구조
중앙 조율자 없이 P2P로 직접 핸드오프. 그래프의 모든 노드가 서로에게 엣지를 가질 수 있다.
장점
구조가 유연하고 특정 지점의 병목이 없다.
단점
에이전트가 늘어날수록 "누가 누구를 호출할 수 있는지" 관계가 복잡해져 디버깅이 어려워진다.
Phase 3

정보 검색 에이전트가 검색을 마치면 스스로 판단해 차트 생성 에이전트로 핸드오프하는 실습으로 이 노선을 직접 만든다.

S

슈퍼바이저선

SUPERVISOR PATTERN

모든 노선이 환승역 하나를 거쳐야 한다. 하위 에이전트는 슈퍼바이저에게 도구처럼 호출되고, 결과도 항상 슈퍼바이저를 거쳐 돌아간다.

라우팅 결정자
슈퍼바이저 하나. 하위 에이전트는 도구(tool)처럼 호출당할 뿐 스스로 라우팅하지 않는다.
통신 구조
하위 에이전트끼리는 서로 모른다. 결과는 항상 슈퍼바이저를 거쳐 오간다(hub-and-spoke).
장점
라우팅 로직이 한 곳에 모여 있어 구조가 명확하고 확장·디버깅이 쉽다.
단점
슈퍼바이저가 병목이 될 수 있고, 하위 에이전트끼리 직접 협업이 필요하면 비효율적이다.
Phase 4·5

웹 분석 → DB 관리를 순차 위임하거나, 최신 검색·내부 DB·FAQ 3개 에이전트 중 질문 유형에 맞는 곳으로 라우팅한다.

H

계층선

HIERARCHICAL PATTERN

슈퍼바이저선을 여러 단으로 쌓은 본선-지선 구조. 총괄역은 팀 단위로만 위임하고, 팀 허브가 다시 세부 정거장에 위임한다.

라우팅 결정자
여러 단의 슈퍼바이저. 최상위는 팀 단위로만 위임하고, 팀 허브가 세부 위임을 다시 결정한다.
통신 구조
슈퍼바이저 패턴을 재귀적으로 쌓은 구조. 각 계층은 자기 하위 계층만 알면 된다.
장점
에이전트 수가 아주 많아져도 슈퍼바이저 한 명이 전부 알 필요가 없어 관심사가 분리된다.
단점
요청이 여러 계층을 거치며 지연(latency)이 늘어나고 구조가 복잡해진다.
Phase 6

Planner가 작업 계획을 세우면 슈퍼바이저가 그 계획대로 조사 에이전트 → 작성 에이전트를 순차·반복 호출해 보고서를 완성한다.

＋

커스텀 연장선

CUSTOM PATTERN

아직 정식 개통 전인 임시 연장선. 슈퍼바이저선은 유지한 채, 필요한 두 정거장만 예외적으로 직접 잇는다.

라우팅 결정자
기본 골격의 결정자(주로 슈퍼바이저)를 유지하되, 특정 구간만 예외 규칙을 추가한다.
통신 구조
정형 패턴 3가지를 문제 상황에 맞게 조합·변형. 패턴 이름보다 "라우팅 권한"과 "상태 공유 방식" 설계가 핵심.
장점
실무 요구사항이 정형 패턴에 딱 안 맞을 때 필요한 만큼만 유연하게 확장할 수 있다.
단점
예외가 늘어날수록 노선도(구조)를 파악하기 어려워질 수 있다.
실무

슈퍼바이저 밑 하위 에이전트끼리 네트워크선처럼 직접 핸드오프를 허용하거나, 조건부 엣지로 특정 상황에만 계층을 건너뛰는 식으로 응용한다.

체크포인트 안내판

Self Check

네트워크선과 슈퍼바이저선, 뭐가 다를까?

"정보 검색 후 차트로 보여줘"라는 요청이 들어왔다고 하자. 네트워크선에서는 검색 에이전트가 결과를 받자마자 스스로 판단해서 차트 에이전트로 곧장 환승시킨다. 슈퍼바이저선에서는 검색 에이전트가 결과를 슈퍼바이저에게 돌려주고, 슈퍼바이저가 다시 판단해서 차트 에이전트를 호출한다. — 이 "직접 환승 vs 항상 허브 경유" 차이를 그림 없이 설명할 수 있으면 7.1 통과.
